# Deploying FinFlow's public demo to Vercel (₹0)

## Read this first: what runs where

| Component | Runs on | Why |
|---|---|---|
| Ingestion, validation, dedup, dbt, DuckDB, Airflow, Telegram alerts, Streamlit dashboard | **Your machine (Docker)** | Vercel is serverless: no persistent disk, ephemeral `/tmp`, 60 s function limit, no Docker/Airflow. More importantly, **real financial data must never leave your machine** (ADR-0007). |
| `site/` — a static, self-contained demo dashboard built from the **synthetic** corpus | **Vercel (Hobby plan, free forever)** | Static files are exactly what Vercel is best at; the free tier covers this forever with no credit card. |

The demo site is regenerated by `finflow export-demo` from `data/sample/`
(generated data committed to the repo). The exporter **refuses** to run against
any dataset not marked `synthetic: true` in its manifest — the public site can
physically never be built from real statements.

## Prerequisites

- The repo pushed to GitHub (`swanaa11/Wallet`) with `site/index.html` committed.
- A Vercel account — sign in **with GitHub** at vercel.com (free, no card).
  Note: Vercel's Hobby plan is for **personal, non-commercial** use — exactly
  what this portfolio project is.

## Method A — Dashboard (recommended, ~3 minutes)

1. Go to **vercel.com → Add New… → Project**.
2. Find **swanaa11/Wallet** in the repository list → **Import**.
   > ⚠️ Import the **Wallet** repo specifically. (A separate `fin.flow` repo
   > without the demo site will fail or deploy an empty page.)
3. In **Configure Project**:
   - **Framework Preset:** `Other`
   - **Root Directory:** click **Edit** and select `site`
   - **Build Command / Output Directory / Install Command:** leave **empty**
     (the site is pre-built static HTML with zero dependencies)
4. Click **Deploy**. You get a live URL like `https://wallet-xxxx.vercel.app`.
5. Every future push to `main` **auto-redeploys** — no extra CI needed.

The repo also carries a **root `vercel.json`** (`outputDirectory: "site"`), so
even if you skip step 3 and import at the repo root, Vercel serves `site/`
statically instead of trying to build a Python function.

## Troubleshooting: "No python entrypoint found …"

```text
Error: No python entrypoint found in default locations, but found potential
entrypoints: src/finflow/cli.py (variable: app)
Add this to your pyproject.toml: [tool.vercel] entrypoint = ...
```

**Cause:** the Vercel project was imported with **Root Directory = repo root**,
so the build saw `pyproject.toml` + Python sources and attempted a *Python
serverless-function build*, scanning for a web entrypoint. FinFlow's pipeline
is not a web app — this build path is simply wrong for it.

**Fix — change the Framework Preset (this is the actual cause):**

The project's Framework Preset was auto-detected as **Python** (because
`pyproject.toml` sits at the repo root). Dashboard settings **override**
`vercel.json`, so the preset must be corrected in the UI:

1. Project → **Settings → General → Framework Preset** → select **Other**
2. While there: **Root Directory → Edit → `site`**; keep Build/Output/Install empty
3. **Save** → **Deployments → ⋯ → Redeploy**

The repo also sets `"framework": null` in `vercel.json`, so fresh imports
never auto-detect Python in the first place.

**Do NOT** add `[tool.vercel] entrypoint = "src.finflow.cli:app"` — that would
try to serve the Typer CLI as a serverless function. FinFlow's architecture
(ADR-0008) keeps the pipeline local; only the static demo belongs on Vercel.

## Method B — CLI

```bash
npm install -g vercel
vercel login                 # GitHub login
cd finflow
vercel --cwd site --prod     # first deploy; accept the defaults
```

## Refreshing the demo data

```bash
make demo-data               # (optional) regenerate the synthetic corpus
finflow export-demo          # rebuild site/index.html from data/sample/
git add site/index.html data/sample && git commit -m "refresh demo data" && git push
```

Vercel detects the push and redeploys automatically.

## Safety checklist

- [x] `site/index.html` is built only from `data/sample/` (synthetic manifest enforced in code)
- [x] No secrets, tokens, or `.env` values are used by or embedded in the site
- [x] Real statements stay in local, gitignored directories and are never exported
- [ ] After setup: confirm your deployed URL shows the "SYNTHETIC DEMO DATA" banner
