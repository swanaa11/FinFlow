# ADR-0008: Vercel hosts the static demo only — the pipeline stays local

Date: 2026-09-12 · Status: Accepted

## Context

The owner wants the project publicly visible ("live") and proposed Vercel as a
free host. Vercel's Hobby plan is genuinely free forever (no credit card,
100 GB transfer/month, over-limit pauses instead of billing — verified
2026-09). However, Vercel is a **serverless** platform: functions have no
persistent filesystem (ephemeral `/tmp`), a 60 s execution ceiling, and cannot
run Docker, Airflow, or background schedulers.

## Decision

- **Vercel hosts exactly one artifact:** `site/` — a self-contained static
  dashboard generated by `finflow export-demo` from the committed **synthetic**
  corpus. Zero build step, zero dependencies, auto-redeploys on push.
- **The pipeline (ingestion, validation, dedup, dbt, DuckDB, Airflow,
  notifications, Streamlit) remains local** — by design (privacy, ADR-0007)
  and by physics (serverless constraints above).

## Rationale

Even if Vercel *could* run the pipeline, it shouldn't: real financial
statements must never leave the owner's machine, and a public host has no role
in the trust boundary. What belongs in "the cloud" is only the publicity
surface — and even that is synthesized data.

## Consequences

- The demo site can never contain real data: the exporter hard-fails unless
  the dataset manifest carries `synthetic: true`.
- The export currently uses lightweight readers (preview of M3 adapters);
  after M8 it switches to reading Gold marts from DuckDB — same output
  contract, better provenance.
- When marts + budgets + anomaly marts exist (M8–M12), the exported JSON
  gains those sections; the deployment process does not change.
